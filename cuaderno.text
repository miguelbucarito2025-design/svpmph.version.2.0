Aquí tienes los estándares y buenas prácticas fundamentales explicados al grano:

---

### 1. Metodología BEM (Block, Element, Modifier)

BEM previene que las clases colisionen entre sí y deja muy claro en el HTML qué hace cada elemento. Se estructura en tres partes:

* **Bloque (`block`)**: El componente independiente (ej. `card`, `btn`, `navbar`).
* **Elemento (`block__element`)**: Una pieza dentro del bloque que depende de él. Se une con **dos guiones bajos (`__`)**.
* **Modificador (`block--modifier`)**: Una variante o estado del bloque o elemento. Se une con **dos guiones medios (`--`)**.

```css
/* Bloque */
.card {
    background-color: #fff;
    border-radius: 8px;
}

/* Elementos dentro del bloque */
.card__title {
    font-size: 1.25rem;
}

.card__button {
    padding: 8px 16px;
}

/* Modificadores (Variantes) */
.card--featured {
    border: 2px solid #3b82f6;
}

.card__button--danger {
    background-color: #ef4444;
}

```

---

### 2. Variables CSS para Colores (Custom Properties)

El mayor error al manejar colores en CSS es nombrarlos por su tono en lugar de por su **función semántica**.

#### ❌ Lo que hay que evitar (Nombres literales):

```css
:root {
    --rojo: #ef4444;
    --azul: #2563eb;
}

```

*¿Por qué?* Si mañana el diseño cambia y el botón principal pasa de azul a verde, tendrás `--azul: #10b981;`, lo cual no tiene sentido.

#### ✅ La buena práctica (Paleta + Uso Semántico):

Se define una paleta base global y luego se mapea según el propósito en la interfaz:

```css
:root {
    /* 1. Paleta base / Primitivos */
    --color-slate-900: #0f172a;
    --color-slate-100: #f1f5f9;
    --color-blue-600: #2563eb;
    --color-red-600: #dc2626;

    /* 2. Variables semánticas (Las que usas en los componentes) */
    --bg-main: var(--color-slate-100);
    --text-primary: var(--color-slate-900);
    --color-primary: var(--color-blue-600);
    --color-danger: var(--color-red-600);
}

/* Uso en el código */
.btn-primary {
    background-color: var(--color-primary);
}

```

---

### 3. Reglas de Nombres de Clases y Formato

* **Siempre `kebab-case**`: Todo en minúsculas y separado por guiones (ej. `.user-profile-header`). Evita `camelCase` o `snake_case` en CSS.
* **Cero IDs en CSS**: Usa IDs (`#mi-id`) únicamente como hooks para JavaScript. En CSS selecciona **siempre por clases** para evitar problemas de especificidad.
* **Prefijos funcionales (Opcional pero muy útil)**:
* `js-`: Indica que la clase la usa JavaScript para manipular el DOM y **no lleva estilos** (ej. `.js-open-modal`).
* `is-` / `has-`: Para estados dinámicos (ej. `.is-active`, `.is-disabled`, `.has-error`).



---

### 4. Arquitectura de Archivos (Para no tener un CSS gigante)

Para evitar archivos de miles de líneas de código, conviene dividir la estructura utilizando la arquitectura **7-1** o un enfoque modular simple:

1. **`base/`**: Resets (`normalize.css`), tipografía global, variables `:root`.
2. **`components/`**: Un archivo CSS por cada componente BEM (`_buttons.css`, `_cards.css`, `_modal.css`).
3. **`layout/`**: Estructura general de la página (`_header.css`, `_sidebar.css`, `_footer.css`).

---

### 5. Regla de Oro: Evitar el Anidamiento Profundo

Intenta no encadenar selectores. Mantenlos lo más planos posible.

```css
/* ❌ Malo: Alta especificidad, difícil de sobrescribir */
div.sidebar ul.menu li.item a {
    color: var(--text-primary);
}

/* ✅ Bueno: Especificidad baja y clara con BEM */
.menu__link {
    color: var(--text-primary);
}

```

Trait de Respuesta HTTP (src/Traits/ResponseTrait.php)
PHP
<?php

declare(strict_types=1);

namespace App\Traits;

/**
 * Trait ResponseTrait
 *
 * Proporciona métodos auxiliares para la estandarización y emisión 
 * de respuestas HTTP en formato JSON.
 *
 * @package App\Traits
 */
trait ResponseTrait
{
    /**
     * Emite una respuesta estructurada en formato JSON y finaliza la ejecución.
     *
     * @param mixed $data Datos o mensaje a responder.
     * @param int $codigoHttp Código de estado HTTP (Por defecto 200).
     * @return void
     */
    protected function jsonResponse(mixed $data, int $codigoHttp = 200): void
    {
        http_response_code($codigoHttp);
        header('Content-Type: application/json; charset=utf-8');

        echo json_encode([
            'status' => $codigoHttp >= 200 && $codigoHttp < 300 ? 'success' : 'error',
            'data'   => $data
        ], JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES);

        exit;
    }
}
Modelo Limpio (src/Models/CuentaModel.php)
PHP
<?php

declare(strict_types=1);

namespace App\Models;

use App\Libs\Exceptions\DatabaseException;

/**
 * Clase CuentaModel
 *
 * Gestiona la persistencia y consultas referentes a las cuentas de usuario.
 *
 * @package App\Models
 */
class CuentaModel
{
    private mixed $db;

    /**
     * Consulta una cuenta de usuario y su perfil asociado mediante el nombre de usuario.
     *
     * @param string $usuario Nombre de usuario a consultar.
     * @return array<string, mixed>|null Retorna los datos de la cuenta o null si no se encuentra.
     * @throws DatabaseException Si ocurre una falla en la ejecución de la consulta SQL.
     */
    public function obtenerPorUsuario(string $usuario): ?array
    {
        $sql = 'SELECT 
                    c.id,
                    c.usuario,
                    c.contrasena,
                    c.estado,
                    c.rol_id,
                    d.nombre,
                    d.apellido
                FROM cuentas c 
                LEFT JOIN datos d ON c.id = d.cuenta_id
                WHERE c.usuario = ? 
                LIMIT 1';

        /** @var array<string, mixed>|false|null $resultado */
        $resultado = $this->db->select($sql, [$usuario], 'row');

        return is_array($resultado) ? $resultado : null;
    }
}
Controlador Modelo (src/Controllers/CuentaController.php)
PHP
<?php

declare(strict_types=1);

namespace App\Controllers;

use App\Models\CuentaModel;
use App\Helpers\Validar;
use App\Libs\Exceptions\AppException;
use App\Traits\ResponseTrait;

/**
 * Clase CuentaController
 *
 * Procesa las peticiones HTTP referentes a las cuentas de usuario.
 *
 * @package App\Controllers
 */
class CuentaController
{
    use ResponseTrait;

    private CuentaModel $cuentaModel;

    public function __construct()
    {
        $this->cuentaModel = new CuentaModel();
    }

    /**
     * Consulta y retorna los datos de una cuenta por su nombre de usuario.
     *
     * @param array<string, mixed> $params Parámetros capturados en la ruta HTTP.
     * @return void Método con retorno void por emitir la respuesta HTTP directamente.
     * @throws AppException Si el parámetro de usuario es inválido o no existe la cuenta.
     */
    public function obtenerPorUsuario(array $params): void
    {
        $usuario = Validar::esNombreUsuario($params['usuario'] ?? null);

        if ($usuario === null) {
            throw new AppException('El nombre de usuario proporcionado no es válido.', 400);
        }

        $cuenta = $this->cuentaModel->obtenerPorUsuario($usuario);

        if ($cuenta === null) {
            throw new AppException('La cuenta solicitada no existe.', 404);
        }

        $this->jsonResponse($cuenta, 200);
    }
}
